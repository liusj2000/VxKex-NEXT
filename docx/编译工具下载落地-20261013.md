## 六、阻断本机构建的缺陷：VxKex 导入重写偶发崩溃

- 现象：`MSB6006: "CL.exe" exited with code -536870909`（`0xE0000003`），并弹出模态框
  `Application Error (VxKex NEXT) — VxKex NEXT could not start because the DLL imports of the main process image could not be rewritten. If the problem persists, please disable VxKex NEXT for this program.`
- VxKex 自己的日志（`%LOCALAPPDATA%\VxKex\Logs\CL-*.vxl`，UTF-16）给出根因：
  ```
  Successfully initialized DLL rewrite subsystem.
  Failed to rewrite DLL imports of the main process image.
  NTSTATUS error code: STATUS_ACCESS_VIOLATION (0xc0000005)
  ```
- 失败分布（当天 15 条 CL 日志）：`CL.exe` 由 **MSBuild 启动**（命令行形如 `"...\VC\bin\amd64\CL.exe" @%TEMP%\tmp*.rsp`）的 **6/6 全部失败**；手动启动的 **9/9 全部成功**（x64/x86、内联参数、自定义 `.rsp`、`/?`）。
- 机制：MSBuild 的 C++ 任务默认经 file tracker（基于 Detours 的注入，SDK `Bin\Detoured.dll` 存在）启动编译器；VxKex 同时在这些进程启动窗口内注入 `KexDll.dll` 并原地重写导入表，两者叠加触发访问违例，VxKex 随即弹窗并终止该进程。
- 作用范围广：IFEO 里只有少数程序被显式配置（如 `cline.exe\VxKex_41C3B7BC7E2582F1`，`KEX_WinVerSpoof=4`、`KEX_DisableForChild=0`），但全局 `{VxKexPropagationVirtualKey}`（`VerifierFlags=2147483648`、`VerifierDlls=KexDll.dll`）会把 `KexDll.dll` 传播给子进程；`cmd.exe`、`MSBuild.exe`、`CL.exe` 本身都没有 IFEO 配置却仍被注入（日志中 `DisableForChild: 0`）。
- 已生效的绕开方式：`/p:TrackFileAccess=false`（不改任何 VxKex 配置）。注意加 `/m` 并行时仍会出现 `LNK1104: cannot open file 'KexDll.lib'` 的链接竞争，串行 `/m:1` 或重跑即可通过。
- 该缺陷属于已安装 VxKex 1.2.3.2463 本身的 bug（涉及 `KexpRewriteImportTableDllNameInPlace` 路径），**尚未在源码中定位或修复**；若要长期修好，需要单独设计和验证，不能只靠绕开。
