# Antigravity 重复下载修复设计（2026-10-23）

## 已确认问题

当前便携版 VS Code 位于 D:\VSCode-win32-x64-1.107.1，扩展 google.google-antigravity-1.9.0。
安装日志有 43 次 `agy.exe --version` 执行失败、23 次发现下载版本的记录；同一版本多次下载，SHA512 校验成功，随后 hub READY。
版本探测函数 mb 使用 execFile、5 秒超时；探测失败后未验证磁盘现有文件的发布校验和，直接进入下载。
下载完成后版本仅存于扩展宿主进程内 Map，重新加载后丢失；所以重复触发。
命令行和无控制台 Node 父进程下 --version 实测正常（1.4.6），尚未复现历史扩展宿主的底层退出原因，不能断言是网络、超时或 Win7 API。

## 修复方案

1. 保留原有版本检查、发布通道判定、正常更新、下载后的完整性校验。
2. 当版本探测失败且已获取官方 manifest 时，计算现有文件 SHA512/SHA256；仅当与本次 manifest 的平台文件校验和完全匹配、校验前后文件指纹一致，才把 manifest 版本放入进程内版本缓存并复用。
3. 不持久化未经验证的版本，不伪造 --version 成功。文件缺失、摘要不匹配、通道切换时保留原下载流程。
4. 版本探测使用隐藏窗口，超时放宽至 30 秒，并补充 code/signal/killed 到失败日志，便于下次确认宿主退出原因。
5. 修复安装完成后缓存版本来源：使用实际下载目标 Kc.targetVersion，防止 manifest 重取后仍缓存旧 Nb（日志已有将 1.4.5 标作 1.1.11 的现象）。

## 变更范围及验证

在扩展目录备份 extension.js 并记录 SHA256，补丁以仓库 docx 下幂等脚本实现，支持回滚；不修改系统 DLL、IFEO、代理或其他项目。
用 VS Code 自带 Node 实际运行提取的原安装判断函数，覆盖同版本复用、探测失败且摘要相符、摘要不符、升级、缺失文件、切换通道、文件校验期间变化等分支；校验实际安装的后端摘要。
不强制重载用户当前 VS Code 会话。补丁在下一次 Reload Window 或重启后加载；真实 UI 重载后的结果须明确列为待用户观察。
