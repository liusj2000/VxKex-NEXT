## 最新停点（2026-11-01 16:06：Bun 在 Win7 下 `ENOTSUP` 与网络失败修复实施完成，全量构建通过并产出最新安装包，待部署验收）

- **解决目标**：
  彻底解决所有基于 Bun 运行时的工具（包括 Claude Code 原生版 `claude.exe` 2.1.314/2.1.316、OpenCode 原生版、独立 `bun.exe` 运行时）在 Windows 7 + VxKex NEXT 环境下出站网络请求报 `ENOTSUP: Unable to connect` 并发送 `TCP RST`，以及入站本地服务（如 OAuth 登录回调、`Bun.serve`）可读触发 `ENOTSUP: operation not supported on socket, read` 的根本故障。
- **根本原因与机制**：
  1. **Win8+ 专属标志未受控**：Bun 的 `uSockets` 在连接探测（`recv(s, NULL, 0, 0x20)`）与常规数据读取（`recv(s, buf, 524288, 0x20)`）中硬编码传入了 Windows 8+ 新增标志位 `MSG_PUSH_IMMEDIATE (0x20)`。Windows 7 的 `mswsock.dll!WSPRecv` 严格拒绝未知标志并返回 `WSAEOPNOTSUPP (10045)`；Bun 拿到 `10045` 后查询 `SO_ERROR` 虽为 0（握手已成功），但 `cmovg` 保留了该错误并映射为 JS 异常 `ENOTSUP`，随后设置 `SO_LINGER` 关闭套接字向对端发送 `TCP RST`；
  2. **`WSOCK32.dll` 延迟加载穿透兼容层**：Bun 运行时通过延迟加载（Delay-Load）按序号导入系统 `WSOCK32.dll`（`Ord 16=recv` 等），而 Win7 原生 `wsock32.dll` 内部静态调用 `WS2_32.dll`。此前 `wsock32.dll` 未列入 `KexDll/dllrewrt.c` 的 `KexIsRewriteForcedWindowsDll` 白名单，导致其静态导入未重定向至 `kxnet.dll`，完全绕过了 VxKex 扩展；
  3. **Win8+ 控制码未拦截**：`uSockets` 与 `libuv` 调用了 Win8+ 的 `SIO_TCP_INITIAL_RTO (0x98000011)`，Win7 原生返回 `WSAEOPNOTSUPP (10045)`。
- **代码实施与修改（全部 5 个文件）**：
  1. [`KexDll/dllrewrt.c`](../KexDll/dllrewrt.c)：在 `KexIsRewriteForcedWindowsDll` 中加入 `wsock32.dll`，当系统加载 `wsock32.dll` 时自动重写其静态导入的 `WS2_32.dll` 为 `kxnet.dll`，保留其原本序号布局；
  2. [`01-Extended DLLs/KxNet/kxnetp.h`](../01-Extended%20DLLs/KxNet/kxnetp.h)：增加 `MSG_PUSH_IMMEDIATE (0x20)`、`SIO_TCP_INITIAL_RTO`、`SIO_LOOPBACK_FAST_PATH` 及 `IPPROTO_TCP` 扩展选项宏；
  3. [`01-Extended DLLs/KxNet/winsock.c`](../01-Extended%20DLLs/KxNet/winsock.c)：
     - 实现 `Ext_recv`、`Ext_recvfrom`、`Ext_WSARecv`、`Ext_WSARecvFrom`：在调用底层 Winsock 之前清除 `MSG_PUSH_IMMEDIATE (0x20)` 标志位；
     - 实现 `Ext_WSAIoctl`：对 Win8+ 控制码 `SIO_TCP_INITIAL_RTO` / `SIO_LOOPBACK_FAST_PATH` 拦截其 `WSAEOPNOTSUPP` 并置 `*BytesReturned=0` 成功返回；
     - 扩展 `Ext_setsockopt`：增加对 `IPPROTO_TCP` 高版本选项的伪装支持；
  4. [`01-Extended DLLs/KxNet/kxnet.def`](../01-Extended%20DLLs/KxNet/kxnet.def)：按 `ws2_32.dll` 精确序号导出 `recv @16`、`recvfrom @17`、`WSAIoctl @74`、`WSARecv @87`、`WSARecvFrom @89`；
  5. [`01-Extended DLLs/KxNet/forwards.c`](../01-Extended%20DLLs/KxNet/forwards.c)：注释掉上述 5 个已接管实现的导出转发宏，消除 LNK4197 链接警告冲突。

  1. `KxBase\console.c` 优化句柄判定：当句柄无显式配置且属于控制台输出句柄时，自动继承活动屏幕缓冲区的 VT 状态，使 ANSI 模拟器正常截获转义码转为 Win32 控制台属性着色。
  2. 引入 `VXKEX_NO_CONSOLE_VT=1` 环境变量应急开关：置 1 时完全禁用 VT 模拟，原生穿透抛出 `ERROR_INVALID_PARAMETER`，强制调用方（PSReadLine/pwsh）自然平滑降级至成熟稳定的 `LegacyWin32Console` Win32 控制台 API 模式。
  3. 执行 `build-installer.cmd` 全量构建 Release x64 与 Win32 产物并打包生成 `KexSetup_Release.exe`。
