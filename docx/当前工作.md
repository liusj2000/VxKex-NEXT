## 最新停点（2026-10-18：OpenCode CLI 在 Win7 下无法运行原因排查完成）

- **排查目标**：检查 `D:\opencode-cli-2.0.6-windows-x64\opencode.exe` 为什么不能正常运行。
- **详细记录**：[OpenCode CLI 在 Windows 7 下无法运行原因深度排查与架构分析](OpenCode在Win7下无法运行原因深度排查与架构分析-20261018.md)。
- **核心结论**：
  1. `opencode.exe` 基于 **Bun** 单文件运行时编译构建，采用 C/S 前后端分离的本地微服务架构（前台 TUI 依赖后台 `opencode serve --service` 监听 `127.0.0.1:49374`）。
  2. **核心阻断（`Bun.serve()` 入站连接重置）**：Bun 底层网络驱动 `uSockets` 在 Win7 上无法正确处理非阻塞 IOCP 状态，导致所有进来的 HTTP 请求（无论是 IPv4 `127.0.0.1` 还是 IPv6 `::1`）在完成 TCP 握手后被服务端底层直接发送 TCP RST（`Recv failure: Connection was reset`），前台 CLI 永远无法与后台服务通信。
  3. **级联衍生故障**：前台探测失败后反复重试启动后台服务，导致 `Managed service port 49374 is already in use` 端口冲突与 `Server process exited with code 3` 崩溃。
  4. **无法绕开**：`--standalone` 内部仍通过动态端口走本地 HTTP，同样抛出 `ClientError: Transport (TypeError: Unable to connect)`。
  5. **建议**：在 Win7 SP1 下放弃基于 Bun 微服务架构的 OpenCode，改用已验证完全可用的 Codex（Rust）或 VS Code 内置插件 / Antigravity。

  1. **Codex TLS 握手与现代根证书缺失**：
     - `codex.exe`（Rust 编译，使用 `reqwest` + `rustls` + `rustls-platform-verifier`）在 Windows 上通过 Win32 CryptoAPI 验证证书。
     - Win7 SP1 原生根证书库停滞在 2009~2011 年，缺少现代云端服务（OpenAI、ChatGPT、Cloudflare）依赖的 ECC 根证书（如 `GlobalSign ECC Root CA - R4`、Google Trust Services 等）。
     - Win7 注册表默认 `CertificateRevocation = 1`，由于 Google CRL 吊销服务器（`c.pki.goog`）在国内被阻断，CryptoAPI 超时后返回 `0x80092013 CRYPT_E_REVOCATION_OFFLINE`，`rustls` 随即拒绝连接。
     - 逆向分析 `codex.exe` 源码确认其支持环境变量 `SSL_CERT_FILE`；配置后 `codex doctor` 连通性诊断全部转绿。
  2. **Claude Code 本地回调失败的两个阶段（详见专门文档）**：
     - **阶段一（端口 54495）**：Windows 系统代理例外白名单 `ProxyOverride` 默认仅为 `<local>`，浏览器将 `http://localhost:<port>` 误转发给局域网远端代理服务器 `192.168.x.x:10809`，代理端无该端口监听返回 TCP RST（10054）。通过将 `ProxyOverride` 设为 `localhost;127.0.0.1;<local>` 解决。
     - **阶段二（端口 49190）**：浏览器直连本机端口成功，但 `claude.exe`（基于 Bun 编译打包）收到 Code 后发起 Token 兑换时，底层网络因 Win7 兼容层非阻塞 IOCP 差异向代理发出 TCP RST，抛出 `Error: connect ECONNREFUSED 192.168.x.x:10809`。认证流程异常终止导致 `claude.exe` 瞬间关闭本地监听端口，浏览器等待 HTTP 响应时再次显示连接重置。
  3. **Claude Code 账号风控（`account_on_hold`）**：
     - 属于 Anthropic 服务端业务级安全风控拦截，因代理出口 IP 节点信誉评分或区域突变触发。
- **已实施解决措施**：
  1. **设置全局用户环境变量（`HKCU\Environment`）**：
     - `SSL_CERT_FILE = C:\Program Files\Git\mingw64\etc\ssl\certs\ca-bundle.crt`
     - `HTTP_PROXY = http://192.168.x.x:10809`
     - `HTTPS_PROXY = http://192.168.x.x:10809`
     - `NO_PROXY = localhost,127.0.0.1`
  2. **关闭网络吊销检查误判**：
     - 将 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings\CertificateRevocation` 设为 `0`。
  3. **修复系统代理白名单，杜绝 localhost 环路走代理**：
     - 将 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings\ProxyOverride` 设为 `localhost;127.0.0.1;<local>`。
  4. **同步 VS Code 用户配置**：
     - 在 `D:\VSCode-win32-x64-1.107.1\data\user-data\User\settings.json` 中，向 `terminal.integrated.env.windows` 与 `claudeCode.environmentVariables` 同步注入 `SSL_CERT_FILE` 与代理环境变量。
  5. **清理陈旧进程**：
     - 终止旧的后台 `codex.exe` 与悬挂的 `claude.exe`。
- **用户后续操作**：
  - 重启 VS Code 或执行 `Developer: Reload Window` 重载窗口以加载新环境变量。
  - 在 Codex 面板重新点击「Sign in with ChatGPT」完成登录（或直接点击「Use API Key」）。
  - Claude Code 如遇到 `account_on_hold`，建议在 `claude.ai` 提交申诉或使用 `ANTHROPIC_API_KEY` 环境变量直接鉴权。
