- **核心修复（详见 [ConPTY 实现问题检查与修复记录](ConPTY实现问题检查与修复-20261017.md)）**：
  1. **定位全量复制 `x64\Release\*` 破坏 VxKex 的根因**：`x64\Release` 混放了属于 `System32\KexDll.dll`、`VxKex\` 与 `VxKex\Kex64\` 三个目录的产物；把 `KexDll.dll` 复制进 `Kex64` 会使 `Kx*.dll` 加载第二份未初始化的 `Kex64\KexDll.dll`（`KexData == NULL`）而崩溃。必须通过 `KexSetup_Release.exe` 安装器进行标准升级。
  2. **恢复 `CloseHandle` 与 `KxAdvapi!CreateProcessAsUserW` 原生导出转发**：移除 `kxbase.def` 中的 `CloseHandle = Ext_CloseHandle`，恢复 `KxBase\forwards.c` 的 `CloseHandle=kernel32.CloseHandle`（避免破坏 Chromium `ScopedHandleVerifier`），并在 `console.c` 中惰性清理已关闭句柄槽位；恢复 `KxAdvapi\forwards.c` 的 `CreateProcessAsUserW=advapi32.CreateProcessAsUserW`。
  3. **静态直连 `CreateProcessW/A/AsUserW` + `KxPseudoConsoleInitialized` 零开销快路径**：移除动态 `LdrGetProcedureAddress` 解析，改为静态导入 `CreateProcessW/A/AsUserW`（`Kx*.dll` 静态导入不被 VxKex 重写）；新增 `KxPseudoConsoleInitialized` 标志，在未调用 `CreatePseudoConsole` 的进程（如 VS Code 主进程/GPU/Renderer）中 100% 原生直通，零加锁、零属性表分配、零 `STARTUPINFOEX` 拷贝。
  4. **对齐 `winconpty.cpp` / Wine / Rust `portable-pty` 细节**：`CreatePseudoConsole` 内部主管道句柄改为 `bInheritHandle = FALSE`（防止无关子进程继承泄漏管道写端），`KxBasepPreparePseudoConsole` 按次复制 `bInheritHandle = TRUE` 的 `hStdInput/Output/Error` 并通过 `STARTF_USECOUNTCHARS` 传递终端行列尺寸，兼容 `wezterm` 预填 `STARTF_USESTDHANDLES` + `INVALID_HANDLE_VALUE` 以及 `Value = hPC` / `Value = &hPC` 两种传参方式。
