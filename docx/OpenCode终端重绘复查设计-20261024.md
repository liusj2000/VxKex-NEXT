5. 区分缓冲区测试、OpenCode TUI、VS Code/winpty、独立 conhost 的验证范围，不用单项通过代替端到端验收。

## 本轮结果与验证边界
- 已复现：TrueType 控制台内，同样的“检查项目状态g”，CP936 的光标 X=13，CP65001 的原生/旧 KxBase X=7。UTF-8 下汉字缺少双格属性，前后端布局产生偏差。
- CP936 的固定中文经 VS Code 自带 winpty 正常输出，并未双写；但 CP936 下部分线框按双格处理。因此撤销“全局切换代码页即可彻底修复”的结论，不提供 CP936 全局配置方案。
- 已修改 conansi.c：在 UTF-8 的 WriteConsoleW 文本路径为常见 BMP 中日韩/全角字符写入带 LEADING/TRAILING 属性的两个 CHAR_INFO 单元；普通字符和控制字符仍走原生路径。DEC 绘图字符也使用同一宽字符输出函数。实际实现 DEC ?7h/?7l 对原生 ENABLE_WRAP_AT_EOL_OUTPUT 的切换。
- 新增 test/terminal-redraw-test.c / .vcxproj 和 terminal-winpty-probe.js。测试自身创建隐藏控制台并使用独立缓冲区，父进程有超时终止保护。
- 最终对照：当前安装版 11 个断言失败；候选版 failures=0 / exit=0。覆盖汉字与线框混排、字符单元属性、覆盖擦除、右边界与换行开关。
- 原有 ansi-features-test 在 TrueType + CP65001 的隐藏控制台中全部通过（5 项功能）。在默认栅格字体或 CP936 下的探索运行曾失败，不以其结果宣称应用回归通过。
- VS Code 自带 node-pty（useConpty=false）+ winpty 对候选 WriteConsoleW 的真实传输得到“BEGIN检查项目状态gEND”，无中文双写。证据 terminal-winpty-fixed-20261024.json。
