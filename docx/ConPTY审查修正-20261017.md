# ConPTY / Console 审查修正（2026-10-17）

## 设计与边界

- 基线 HEAD：cf5eb60；开始时工作区无修改。
- 仅修改源码、构建与独立测试，不部署安装目录 DLL，不改变 IFEO 或系统策略。
- 保留现有纯 C、NT 堆和旧 SDK 约定。
- 对象改为首字段 DWORD Magic = 0x4350584B 的 KEX_PSEUDOCONSOLE；使用活动对象链表防止仅凭可伪造签名接受对象。
- 使用同一个静态初始化 SRW 锁保护活动对象、属性映射及取用句柄。启动前在锁内复制临时可继承句柄，解锁后调用原生进程 API，避免 Close 并发释放对象。
- 属性同时支持 HPCON 与 &HPCON，SEH 保护指针读取。映射表容量耗尽必须失败；Delete 清理槽，Close 将现有绑定标为失效，禁止静默退回普通启动。
- 拦截 InitializeProcThreadAttributeList 跟踪原生属性是否为空；仅对已知为空且只有伪终端绑定的属性表降级 STARTUPINFO。其他属性保留原生扩展表。
- CreateProcessA/W 和 CreateProcessAsUserW 共用准备逻辑：局部拷贝、隐藏窗口、标准句柄、强制继承、CREATE_NO_WINDOW。KxAdvapi 的 AsUserW 入口也转到 KxBase。
- Console Mode 先原生调用，仅 ERROR_INVALID_PARAMETER 时剥离相应 VT 位重试。输入 0x4/0x8 是 ECHO/WINDOW，不能剥离。按句柄记录成功模式，保留既有 ANSI 输出解析器。
- 仍是管道后端：不提供真实控制台缓冲区、resize 通知、完整 VT 输入转换或关闭时自动终止子进程。不得声称 Rust codex / Node 22 / opencode 已端到端兼容。

## 尚未验收 / 明确限制

- 仅部分 A/B/C 分层测试已运行，D（Cline/codex/opencode 端到端）未运行；未部署，无整机回归结论。
- AsUserW 仅测试 NULL token 当前用户路径，不代表跨用户权限路径通过。
- 显式 PROC_THREAD_ATTRIBUTE_HANDLE_LIST 不能自动继承私有管道副本，目前明确 ERROR_NOT_SUPPORTED；不丢弃或偷偷扩大调用方 allow-list。
- 未经本 Hook Initialize 的属性表保守保留原生扩展信息，其空表兼容尚未单独测试。不得直接解读 Win7 私有表布局。
- 64 个并存属性表、128 个 Console 模式槽存在容量上限，满表显式失败。CloseHandle Hook / FreeConsole 清理模式槽；绕过 Hook 的原生 CloseHandle 仍可能留下槽。
- 活动对象登记与锁避免关闭并发释放；基于堆地址的 HPCON 在地址重用后的旧句柄 ABA 问题仍属于指针句柄接口限制，不能宣称无限期识别所有旧句柄。
- resize 无真实终端通知、Close 不自动结束已创建子进程；模式位欺骗不等于 VT 输入转换。
- Win32/Debug、多线程压力、超大输出、原生属性组合和显式容量耗尽尚未测试。
- API Set 实际在 redirects.h，dllrewrt.c 删除七字符 -lX-Y-Z 后缀，所以 console-l1-2-0 / l1-2-1 均已覆盖，无需修改 apiset.c。
