## 一、管理员安装失败：INetFwRule3 不存在

先前按用户要求调用本机 app-server 的 windowsSandbox/setupStart（mode=elevated，cwd=D:\project\VxKex-NEXT），收到 started=true，随后 setupCompleted success=false：

```
helper_firewall_rule_create_or_add_failed:
CoCreateInstance NetFwRule failed: HRESULT(0x80004002)
```

本轮创建未保存的 HNetCfg.FWRule COM 对象，对三个接口执行 QueryInterface，未向防火墙添加任何规则：

| 接口 | 本机实测 |
| --- | --- |
| INetFwRule | S_OK，0x00000000 |
| INetFwRule2 | S_OK，0x00000000 |
| INetFwRule3 | E_NOINTERFACE，0x80004002 |

BFE、MpsSvc 服务均为 Running。Microsoft 文档规定 Rule2 最低 Win7，Rule3 最低 Win8。参考上游当前 firewall.rs，ensure_block_rule 创建 INetFwRule3，后续使用 SetLocalUserAuthorizedList 设置按用户隔离的规则并回读校验。其失败文本与本机日志一致。上游 main 仅作实现参考，本轮未证明其提交号与本机 alpha 二进制完全一致。

据此，当前安装错误与 Win7 缺少新版防火墙接口吻合；重复安装、版本伪装、仅勾选 EXE 的 VxKex 属性均不能补出该接口。KxCom 当前 Ext_CoCreateInstance 只补 COM 初始化并调用原生 CoCreateInstance，未实现 Rule3 代理。

不能把 Rule3 简单换成 Rule2或让缺失方法返回成功：Codex 使用其用户 SID 范围属性实现网络隔离，跳过会改变沙箱约束。完整适配需要实际可验证的 Win7 网络隔离后端。

## 二、unelevated 执行失败：CSR 调用返回 STATUS_ACCESS_DENIED

用本机 CLI 直接复现（不更改保存配置）：

```
codex.exe -c windows.sandbox="unelevated" sandbox -C D:\project\VxKex-NEXT -P :workspace -- C:\Windows\System32\cmd.exe /d /c echo SANDBOX_TRACE_OK
```

未调试时真实退出码为 -1073741502，即 0xC0000142。普通 cmd.exe 基线测试在相同父环境中退出 0。

随后仅调试新建的诊断进程树。通过加载器消息确定：

```
Init routine ... for DLL "C:\Windows\system32\kernel32.dll"
failed during DLL_PROCESS_ATTACH
Process initialization failed with status 0xc0000142
```

受限 cmd.exe 已加载 System32\KexDll.dll 和 VxKex\Kex64\KxNt.dll。该失败不是“尚未启用 VxKex”或单纯缺一个静态导出。KxNt 中 CsrClientConnectToServer 是到原生 ntdll 的导出转发。

进一步用临时断点读取本机对应分支（断点只写入诊断进程内存，命中后恢复原字节与指令指针）：

- ntdll RVA 0x19CA0：内部连接函数返回 0。
- ntdll RVA 0x19BEE：CsrClientCallServer 调用返回 0xC0000022。
- kernel32 RVA 0x16DC2：CsrClientConnectToServer 返回 0xC0000022。
- kernel32 RVA 0x1541E：调用方接到相同错误，进入失败路径。
- 最终受限子进程和诊断 CLI 均退出 0xC0000142。

这把问题缩小到 Windows CSR 通信阶段的拒绝访问，而非一般 PowerShell 安装问题。尚未定位到服务端具体访问对象或验证哪项 token/desktop/console 条件导致拒绝；也尚未通过无 VxKex 的同条件对照，不能断定全部责任在 VxKex 或 Codex 任一方。

## 三、进程权限对照：补 SYSTEM 不是解决方案

只读检查发现：普通诊断进程 DACL 包含当前用户、SYSTEM 和登录 SID；受限进程及初始线程仅包含登录 SID 全权和 OWNER RIGHTS 的 READ_CONTROL。

为验证这一线索，仅给新建的 echo 诊断子进程和初始线程添加 SYSTEM 授权。第一次调试事件自带句柄缺 WRITE_DAC，设置返回 5；以所需权限重新打开这些临时对象后，设置均返回 0。但 CSR 调用仍返回 0xC0000022，最终仍退出 0xC0000142。因此该 ACL 差异不足以单独解释失败，不应据此批量修改系统或沙箱权限。

未修改文件、注册表、桌面或其他系统对象 ACL；这些诊断进程已退出。
