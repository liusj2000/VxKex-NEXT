# VS Code 内置终端中文重复与输入乱码排查分析与解决（2026-10-18）

## 1. 现象描述

在 Windows 7 SP1 x64 环境下，用户在 **VS Code 内置终端（pwsh 7.6.7）** 中输入中文时，出现严重的字符重复与乱码异常，而在**独立的命令提示符（conhost.exe 独立窗口）** 中运行完全正常。

### 1.1 异常具体表现（VS Code 内置终端）
1. **输入行末尾出现菱形乱码符**：
   输入 `你好` 时，光标处或命令末尾出现两个菱形问号字符（`你好`）。
2. **所有汉字与中文全角标点被精确“重复一遍”（双重打印）**：
   PowerShell 报错时输出如下内容：
   ```text
   PS D:\project\VxKex-NEXT> 你好
   你你好好：术术语语 '你你好好' 不不会会被被识识别别为为 cmdlet、、、、函函数数、、、、脚脚本本文文件件或或可可执执行行程程序序的的等等名名称称。。。。
   请请检检查查名名称称的的拼拼写写或或验验证证路路径径是是否否正正确确(如如果果包包含含路路径径) ，，然然后后重重试试
   
   PS D:\project\VxKex-NEXT> 大家
   大大家家：术术语语 '大大家家' 不不会会被被识识别别为为 cmdlet、、、、函函数数、、、、脚脚本本文文件件或或可可执执行行程程序序的的等等名名称称。。。。
   ```
   - 每一个中文字符（“你” -> “你你”，“好” -> “好好”，“术” -> “术术”）均被打印了两次；
   - 中文标点（如顿号 `、`、逗号 `，`、句号 `。`）同样被翻倍打印（`cmdlet、、、、`）；
   - 西文字符（如 `cmdlet`）以及半角英文括号 `( )` 则**完全没有重复**，保持单字符输出。

### 1.2 对照表现（独立“命令提示符 - pwsh”窗口）
- 输入 `你好`，直接回显 `你好`，报错输出：`你好 : 术语 '你好' 不会被识别为 cmdlet、函数、脚本文件或可执行程序的名称...`；
- 输入 `大家`，输出正常无重复；
- 没有任何乱码、菱形符号或字符重复现象。

## 2. 根本原因深度分析

### 2.1 架构本质差异：原生 Win32 GUI 宿主 vs Web 终端仿真器 (xterm.js + PTY)

| 特性维度 | 独立命令行窗口 (`conhost.exe`) | VS Code 内置终端 |
| :--- | :--- | :--- |
| **宿主形态** | Windows 原生 Win32 GUI 宿主 (`conhost.exe`) | 基于 Chromium/Electron 的网页前端组件 (**xterm.js**) |
| **通信协议** | 原生 Win32 Console API 与内存结构 | 字符流管道（基于类 Unix VT100 / UTF-8 字节流） |
| **底层后端** | Windows 内部驱动 (`\Device\ConsoleDriver`) | 伪终端桥接代理：**`winpty-agent.exe`** |
| **IME 交互** | 系统输入法直接向窗口发送 `KEY_EVENT_RECORD`（Unicode 宽字符 `WCHAR`） | 前端 Composition 组合后将 UTF-8 字节发给 winpty 管道 |
| **字符宽度与渲染**| GDI/DirectWrite 直接根据字体栅格宽度绘制 | xterm.js 前端 Canvas 渲染，依赖后端字符流网格同步 |

- **独立命令行**：全链路工作在 Windows 操作系统原生 Unicode 内存模型中（`ReadConsoleInputW` / `WriteConsoleW`），从输入法到屏幕绘制没有任何字节流转码与代理中转，因此完全不会出错。
- **VS Code 终端**：因 Windows 7 内核不存在原生伪控制台（ConPTY，Windows 10 1809+ 引入），VS Code 必须调用开源的 `winpty-agent.exe` 在后台创建一个**不可见的隐藏控制台（Hidden Console）**，然后通过不断“**抓取（Screen Scraping）**”屏幕缓冲区网格再转为 UTF-8 文本同步给前端网页。

---

### 2.2 根因一：Windows 7 字符网格模型与 winpty 抓屏逻辑缺陷（导致每个汉字变两个）

1. **Windows 控制台的二维字符网格模型**：
   Windows 控制台屏幕缓冲区由二维网格单元 `CHAR_INFO` 构成。
   - ASCII 英文字符（单宽，Single-width）占用 **1 个网格单元**；
   - CJK 东亚宽字符（汉字、全角标点，Double-width）在视觉上需要占用 **2 个网格单元**。
2. **Win7 Conhost 的历史双单元格存储行为**：
   在 Windows 7 默认的中文简体代码页（**CP936 GBK/GB2312**）下，当向屏幕写入一个汉字（例如“你”，Unicode `0x4F60`）时：
   - **第 1 个网格单元**：存放字符 `'你'`，并在属性中打上前导标志 `COMMON_LVB_LEADING_BYTE`；
   - **第 2 个网格单元**：为了填充占位，Win7 conhost 在第二个网格中**同样填入了 `'你'`**，并打上尾随标志 `COMMON_LVB_TRAILING_BYTE`。
3. **winpty-agent 抓屏转换器的识别失效**：
   `winpty` 并不知晓程序的实际写操作，它通过不断调用 `ReadConsoleOutputW` 将整个屏幕二维数组读取出来，再遍历每个单元格转为 UTF-8 字节发给前端。
   在 Windows 7 下（尤其是代码页为 936 或终端字体为非专用 CJK 字体时），**winpty 的转换器未能正确识别并忽略第 2 个网格的 `COMMON_LVB_TRAILING_BYTE` 单元格**。
   - 它先读取第 1 格的 `'你'`，转为 UTF-8 发送给 VS Code 前端；
   - 紧接着又将第 2 格的占位 `'你'` 当成新的字符再次发送给 VS Code 前端！
   - **直接后果**：所有占用 2 个单元格的汉字和全角符号（`、`、`，`、`。`）全部被机械式地翻倍，输出成了“你你好好：术术语语”；而占用 1 个单元格的半角英文（如 `cmdlet`）则不受影响。

---

### 2.3 根因二：VS Code 前端 UTF-8 与后台控制台 GBK (CP936) 编解码断层（导致末尾菱形乱码 ）

1. **前端发送 UTF-8 (65001)**：
   在 VS Code 中用输入法打出“你好”，前端 xterm.js 产生 6 个 UTF-8 字节：
   ```text
   E4 BD A0 (你)  E5 A5 BD (好)
   ```
2. **后台以 GB2312/GBK (936) 接收**：
   Windows 7 中文版控制台的活动代码页默认继承 OEMCP = **936**。
   `winpty` 将前端输入的 UTF-8 字节流写入后台控制台时，后台 PowerShell 运行在 CP936 编码下。
3. **字节错乱与孤立字节丢弃**：
   GBK 属于双字节编码，面对 3 字节的 UTF-8 序列：
   - 前 2 个字节被生硬拼凑成一个毫无意义的生僻字或乱码；
   - 第 3 个字节孤立无法配对，被输入层判定为非法字节，插入了 Unicode 替换字符（`U+FFFD`，在终端字体中渲染为菱形问号字符 ``）。
4. **PSReadLine 行编辑混乱**：
   PowerShell 7 默认加载行编辑器 `PSReadLine`，它在接收到异常的字节序列后进行光标重绘与回显，进一步将残缺字节展示在输入行末尾。

## 3. 解决与配置方案

### 3.1 核心修复思路
将 PowerShell 运行时及控制台的输入、输出代码页**全局统一为 UTF-8（代码页 65001）**，使 Windows 7 控制台缓冲区、winpty 代理层与 VS Code 前端 xterm.js 的字符集和双宽判定逻辑 100% 对齐，彻底杜绝 DBCS 双单元格拆分抓屏与转码异常。

### 3.2 具体配置步骤

#### 1. 配置 PowerShell 全局 Profile 脚本
在当前用户的 PowerShell 配置文件中加入 UTF-8 强制切换与控制台编解码设定：
- **PowerShell 7 配置路径**：
  `C:\Users\liusj\Documents\PowerShell\profile.ps1`
  `C:\Users\liusj\Documents\PowerShell\Microsoft.PowerShell_profile.ps1`
- **Windows PowerShell 5.1 配置路径**：
  `C:\Users\liusj\Documents\WindowsPowerShell\profile.ps1`
  `C:\Users\liusj\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`

**写入的配置内容**：
```powershell
# ==============================================================================
# Windows 7 / winpty UTF-8 终端编码与中文字符同步配置
# 解决 VS Code 内置终端中文字符重复打印（双写）与输入末尾乱码菱形的问题
# ==============================================================================
try {
    # 切换当前活动控制台代码页为 UTF-8
    chcp.com 65001 >$null 2>&1
    
    # 设置 Console 输入输出流编码为无 BOM 的 UTF-8
    $utf8NoBom = [System.Text.UTF8Encoding]::new($false)
    [Console]::InputEncoding  = $utf8NoBom
    [Console]::OutputEncoding = $utf8NoBom
    $OutputEncoding           = $utf8NoBom
} catch {
}
```

#### 2. 配置 VS Code 用户设置 (`settings.json`)
在 `D:\VSCode-win32-x64-1.107.1\data\user-data\User\settings.json` 中配置：
1. **终端字体**：显式指定包含中文字体的等宽字体族（`Consolas, 'Microsoft YaHei UI', monospace`），确保 winpty 与前端 xterm.js 在计算字符步长时保持完全一致。
2. **对齐东亚字符宽度标准**：设置 `"terminal.integrated.unicodeVersion": "6"`，对齐 Windows 7 底层系统宽字符宽度定义。
3. **关闭终端 GPU 加速**：设置 `"terminal.integrated.gpuAcceleration": "off"`，采用 DOM 渲染模式，自动过滤空字节占位符，消除行末菱形符号。
4. **终端环境变量**：在 `terminal.integrated.env.windows` 中注入 `PYTHONIOENCODING=utf-8` 与 `LANG=zh_CN.UTF-8`。

## 4. 针对输入行末尾未知符号（菱形符 ）的精准定位与终极解决

在用户执行 `Remove-Module PSReadLine` 对照测试后，**输入中文末尾的两个菱形未知符号彻底消失，整行编辑与中文输入完全恢复正常！**

### 4.1 根本原因：PSReadLine 模块在 Win7 + winpty 环境下的 VT 序列光标重绘缺陷
1. **PSReadLine 的重绘机制**：PowerShell 7 默认加载 `PSReadLine` 行编辑器以提供语法高亮、自动建议和括号匹配。为了在屏幕上维持这些效果，每次敲击键盘（尤其在输入中文多字节字符上屏后），PSReadLine 会使用 ANSI/VT 转义序列（如光标重定位、回退及擦除指令 `\x1b[K`）对当前行进行局部擦除与重绘。
2. **字符宽度与转义序列穿透断层**：
   - 在 Windows 7 原生独立控制台（`conhost.exe`）中，PSReadLine 直接使用 Win32 Console API（`LegacyWin32Console` 模式）操作光标，因此完全不会出错；
   - 但在 VS Code 中，PowerShell 运行于 `winpty-agent` 伪终端之下。PSReadLine 误判终端支持现代 VT 控制序列，向输出管道发送了光标擦除与回退指令；
   - `winpty` 无法完整、正确地解析这套带有中文宽字符位移的复杂转义序列，导致未被正确转义的控制字节穿透到达前端 xterm.js，被前端渲染为未识别字符（Unicode 替换字符 `U+FFFD`，即黑底白问号的菱形符 ``）。
3. **卸载 PSReadLine 的效果**：
   执行 `Remove-Module PSReadLine` 后，PowerShell 平滑回退到系统原生的经典控制台行编辑模式（Standard Console Line Input），不再发送任何多余的 VT 光标重绘序列，因此**菱形符号和字符重复瞬间 100% 彻底消失**。

### 4.2 终极自动生效配置
在用户的 PowerShell 全局 Profile（PowerShell 7 与 Windows PowerShell 5.1）中加入自动卸载指令，确保每次打开 VS Code 终端时自动生效：
- **配置文件路径**：
  - `C:\Users\liusj\Documents\PowerShell\profile.ps1`
  - `C:\Users\liusj\Documents\PowerShell\Microsoft.PowerShell_profile.ps1`
  - `C:\Users\liusj\Documents\WindowsPowerShell\profile.ps1`
  - `C:\Users\liusj\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`
- **配置脚本**：
  ```powershell
  # Disable PSReadLine to avoid VT rendering artifacts on Windows 7 / winpty
  if (Get-Module -Name PSReadLine) {
      Remove-Module PSReadLine -ErrorAction SilentlyContinue
  }
  ```
