# 控制台 SGR 38/48 扩展颜色（256 色与 24-bit RGB）量化支持设计（2026-11-01）

## 1. 问题背景与现象

在 Windows 7 SP1 x64（VxKex NEXT 环境）下运行 OpenCode（`opencode2-node.exe`）触发交互式 `Questions` 问答菜单时，用户实测反馈：
- 在独立 `pwsh`（原生 `conhost.exe`）与 VS Code 内置终端（基于 `winpty-agent.exe` 抓取隐藏 `conhost.exe` 屏幕缓冲区）中，按 `↑` / `↓` 方向键移动选项焦点时，内部选中项确实发生了切换（按回车或空格可切换对应项的勾选状态），但**当前箭头所在的焦点行没有任何颜色高亮或反色变化，所有选项行在视觉上完全相同，无法分辨当前选中了哪一项**。

## 2. 根因定位

### 2.1 OpenCode 问答菜单焦点高亮渲染机制

通过对 `D:\project\claude-code-engineering\node-v22.22.2-win-x64\node_modules\@opencode\cli-node\bin\opencode2-node.exe` 内置 TUI 组件（偏移 `106882000`～`106891500` 及 `119780000`～`119785500`）与主题定义（偏移 `106318000`～`106330000`、`117965000`～`117971000`）的逆向分析，确认 `Questions` 组件在渲染每个选项行（索引 `oo()`，焦点判定 `Zi = () => oo() === wn.selected`）时，完全依赖前景/背景颜色属性区分焦点态与非焦点态，**并不在焦点行前添加 `>` 字符前缀**：

```javascript
// 选项序号 (1., 2., ...)
backgroundColor: en.background.raised.base,          // #141414 -> RGB(20, 20, 20)
fg: Zi() ? en.text.formfield.focused : en.text.muted // 焦点: #fab283 RGB(250, 178, 131); 非焦点: #808080 RGB(128, 128, 128)

// 多选复选框 ([ ] / [✓])
fg: Zi() ? en.text.formfield.focused
  : co() ? en.text.formfield.selected
         : en.text.muted

// 选项主标题 (Label)
backgroundColor: en.background.raised.base,          // #141414 -> RGB(20, 20, 20)
fg: Zi() ? en.text.formfield.focused : en.text.formfield.base // 焦点: #fab283 RGB(250, 178, 131); 非焦点: #eeeeee RGB(238, 238, 238)

// 选项说明文字 (Description)
fg: en.text.muted                                    // #808080 -> RGB(128, 128, 128)
```

在底层终端渲染器中，OpenCode 将上述颜色统一编码为 **ANSI SGR 38（扩展前景色）与 SGR 48（扩展背景色）** 序列输出：
- 24-bit TrueColor：`\x1b[38;2;R;G;Bm`、`\x1b[48;2;R;G;Bm`
- 256 色索引模式：`\x1b[38;5;Nm`、`\x1b[48;5;Nm`

### 2.2 `KxBase` (`conansi.c`) 对 SGR 38/48 的丢弃缺陷

在 [`01-Extended DLLs/KxBase/conansi.c`](file:///D:/project/VxKex-NEXT/01-Extended%20DLLs/KxBase/conansi.c#L372-L384) 的 `ExecuteCSISetGraphicsRendition` 函数中：

```c
		case 38:	// Extended foreground color setting
		case 48:	// Extended background color setting
			KexLogDebugEvent(
				L"Extended %s color setting ignored",
				Parameter == 38 ? L"foreground" : L"background");
			KexDebugCheckpoint();
			return FALSE;
```

该实现存在两个严重问题：
1. **完全丢弃扩展颜色**：遇到 `38` 或 `48` 时未解析后续的 `5;N`（256 色）或 `2;R;G;B`（24-bit RGB）子参数，未映射到 Win32 控制台 16 色属性（`FOREGROUND_*` / `BACKGROUND_*`）；
2. **提前中断整条复合 SGR 序列**：直接执行 `return FALSE;`，跳过了函数末尾的 `SetConsoleTextAttribute(ConsoleHandle, TextAttribute)`，导致同一条序列中位于 `38`/`48` 之前的属性（如 `0` 复位、`1` 高亮等）也一并失效。

其直接后果是：无论在独立 `pwsh`（直接显示 `conhost.exe` 窗口）还是在 VS Code 终端（由 `winpty-agent.exe` 调用 `ReadConsoleOutputW` 采集 `conhost.exe` 缓冲区字符属性 `wAttributes` 并转译为 ANSI 序列），所有文字均维持默认属性 `0x0007`，焦点行、普通行与说明文字无任何视觉差异。

## 3. 量化映射方案设计

Win32 传统控制台（`conhost.exe`）每个字符单元支持 4-bit 前景色（`0..15`）与 4-bit 背景色（`0..15`）。为兼顾独立 `pwsh`（深色背景）与 VS Code 终端（可能使用浅色或深色主题，经 `winpty` 转译默认属性 `0x07`），量化算法需满足以下关键约束：

### 3.1 核心设计约束

1. **深灰背景抑制（防止整屏泛灰或浅色主题下出现黑底色块）**：
   - 现代 TUI 深色主题大量使用 `#0a0a0a`（`10,10,10`）、`#141414`（`20,20,20`）、`#1e1e1e`（`30,30,30`）作为面板底色（`background.base` / `background.raised.base`）。
   - 若简单按最近邻映射为深灰 `BACKGROUND_INTENSITY`（`0x80`），在 `conhost.exe` 中整块界面会变成刺眼的浅灰色，在 VS Code 浅色主题下也会被 `winpty` 渲染成深灰色块。
   - **规则**：对于背景色（`IsBackground == TRUE`），当无彩色（低饱和度 `chroma < 32`）且亮度较低（`max(R, G, B) < 65`）时，统一映射为默认黑底 `0`（对应 `winpty` 默认背景），仅当背景色具有明显色彩饱和度或中高亮度（如选中背景色块、Diff 绿/红底色）时才映射为对应的非零背景色位。

2. **浅白无彩色前景保持默认属性 `0x07`（兼顾深色 `pwsh` 与浅色 `VS Code`）**：
   - 在 `winpty` 中，Win32 前景属性 `7`（`FOREGROUND_RED | FOREGROUND_GREEN | FOREGROUND_BLUE`，不带 `FOREGROUND_INTENSITY`）被识别为控制台默认前景色，转译为终端默认前景（在深色终端中为白字，在 VS Code 浅色主题中自动呈现为清晰的黑字）。
   - 若将常规白字 `#eeeeee`（`text.formfield.base`）或 `#ffffff`（`text.base`）映射为 `15`（`0x0F` 亮白，对应 `winpty` 的 `\x1b[97m`），在 VS Code 浅色主题（白底）下会变成白底浅灰字，导致难以阅读。
   - **规则**：无彩色（`chroma = max - min < 32`）前景色按亮度分段：
     - `max < 48`：`0`（黑色）
     - `48 <= max < 165`：`FOREGROUND_INTENSITY`（`0x08` 暗灰，如 `text.muted` `#808080`，使非焦点序号、复选框与说明文字呈现柔和灰色）
     - `max >= 165`：`FOREGROUND_RED | FOREGROUND_GREEN | FOREGROUND_BLUE`（`0x07` 标准白/默认前景，使常规正文与非焦点标题在深浅主题下均清晰锐利，同时若同一 SGR 序列显式指定了 `1` 粗体/高亮则保留 `FOREGROUND_INTENSITY`）

3. **有彩色（Chromatic）去白基线相对色度提取（确保柔和主题色精准映射为鲜明彩色）**：
   - 现代 TUI 的焦点/强调色常采用高明度柔和色（Pastel Color），例如 OpenCode 默认深色主题的焦点色 `orange.200` 为 `#fab283`（`R=250, G=178, B=131`）。
   - 注意 `#fab283` 的 `B=131 > 128`：若直接按绝对阈值 `channel >= 128` 判定 RGB 通道位，会错误地将 R、G、B 三个位全部置 1，退化为白色 `0x07`/`0x0F`，导致焦点色与普通文本再次撞色！
   - **规则**：当 `chroma = max(R,G,B) - min(R,G,B) >= 32` 时，先减去三通道最小值 `min`（剥离白色去饱和基线），计算纯色度分量：
     - `dr = R - min`、`dg = G - min`、`db = B - min`
     - 若 `dr * 3 >= chroma`（即该通道贡献不低于色度跨度的 1/3），置 `RED` 位；
     - 若 `dg * 3 >= chroma`，置 `GREEN` 位；
     - 若 `db * 3 >= chroma`，置 `BLUE` 位；
     - 若 `max >= 140`（对于前景色），置 `INTENSITY` 位（高饱和度亮色）。
   - **验证 OpenCode 关键色板映射结果**：
     - 焦点项 `orange.200` `#fab283` (`250, 178, 131`)：`min=131, chroma=119` -> `dr=119, dg=47, db=0` -> `RED | GREEN | INTENSITY`（`0x0E` 亮黄/金色），与非焦点标题 `0x07`（白/默认）及非焦点序号 `0x08`（暗灰）形成极强对比；
     - 浅色主题焦点项 `blue.200` `#3b7dd8` (`59, 125, 216`)：`min=59, chroma=157` -> `dr=0, dg=66, db=157` -> `GREEN | BLUE | INTENSITY`（`0x0B` 亮青蓝）；
     - 主题强调色 `purple.200` `#9d7cd8` (`157, 124, 216`)：`min=124, chroma=92` -> `dr=33, dg=0, db=92` -> `RED | BLUE | INTENSITY`（`0x0D` 亮品红）；
     - 成功/新增色 `green.200` `#7fd88f` (`127, 216, 143`)：`min=127, chroma=89` -> `dr=0, dg=89, db=16` -> `GREEN | INTENSITY`（`0x0A` 亮绿）；
     - 错误/删除色 `red.200` `#e06c75` (`224, 108, 117`)：`min=108, chroma=116` -> `dr=116, dg=0, db=9` -> `RED | INTENSITY`（`0x0C` 亮红）；
     - 链接/青色 `cyan.200` `#56b6c2` (`86, 182, 194`)：`min=86, chroma=108` -> `dr=0, dg=96, db=108` -> `GREEN | BLUE | INTENSITY`（`0x0B` 亮青）。

### 3.2 256 色（`38;5;N` / `48;5;N`）映射

- `0..7`：直接对应标准 ANSI 30..37 / 40..47 的 8 种基础色；
- `8..15`：直接对应标准 ANSI 90..97 / 100..107 的 8 种高亮色；
- `16..231`（6×6×6 RGB 立方体）：
  - `idx = N - 16`
  - `r_idx = idx / 36`，`g_idx = (idx / 6) % 6`，`b_idx = idx % 6`
  - 各通道还原为 0..255：`c = (c_idx == 0) ? 0 : (c_idx * 40 + 55)`，再调用 `QuantizeRgbToConsoleColor(R, G, B, IsBackground)`；
- `232..255`（24 级灰度阶梯）：
  - `gray = (N - 232) * 10 + 8`，再调用 `QuantizeRgbToConsoleColor(gray, gray, gray, IsBackground)`。

### 3.3 复合 SGR 参数推进与分隔符兼容

1. 将 `MAX_CSI_PARAMETER_COUNT` 从 `16` 提升至 `32`，确保同时包含复位、样式、前景 RGB、背景 RGB 的长复合序列（如 `\x1b[0;1;38;2;250;178;131;48;2;20;20;20m`）不会因参数数量超限而被丢弃；
2. 在 CSI 参数解析器中同时支持 `;` 与 `:`（ITU T.416 子参数分隔符）；
3. 在 `ExecuteCSISetGraphicsRendition` 中：
   - 记录显式 `SGR 1`（`ExplicitBold`），防止同一序列后续的 `30..38` 覆盖掉显式粗体/高亮请求；
   - 在 `case 38:` 与 `case 48:` 中正确消费后续 2 个参数（`5;N`）或 4 个参数（`2;R;G;B`），递增 `ParameterIndex` 并继续循环，最后统一调用 `SetConsoleTextAttribute(ConsoleHandle, TextAttribute)`。
