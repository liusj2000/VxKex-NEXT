# 控制台 VT 转义序列完整修复与 TUI 渲染优化（2026-10-23）

## 1. 背景与排查现象

在 Windows 7 SP1 x64（VxKex NEXT 环境）下运行交互式终端现代 TUI 程序（如 `opencode2-node` / Node.js Ink / React TUI 等）时，控制台界面出现三类严重显示缺陷：

1. **左侧边缘纯文本漏码（`15;1H`、`28;1H`、`34;1H`）**：光标移动（CUP）转义序列的尾部被当作可打印文本直接绘制到了控制台左侧边缘；
2. **弹窗覆盖层背景残留与残影（Ghost Text）**：弹出“选择模型”或配置菜单时，原界面的“Ask”、“Buil”等提示文本与 Logo 破碎地重叠在菜单周围和背景上，无法干净清除；
3. **大量重复的 `'aaaaaaa'` 与 `'~'` 符号**：边框与阴影色块变成纯字母 `'a'`（如 `aaaaaaaaaaaaa`），提示符圆点变成 `'~'`。

---

## 2. 根本原因深层溯源

经过源码级调试与 Win7 conhost 原生行为分析，定位出以下核心根因：

### 根因一：`Ext_SetConsoleMode` 误判 Win7 原生 VT 能力导致 ANSI 解释器被彻底停用

在 Windows 7 conhost 中，`SetConsoleMode` 传入未定义标志（如 `ENABLE_VIRTUAL_TERMINAL_PROCESSING` `0x0004`）时，**原生 API 并不返回 `FALSE`，而是静默返回 `TRUE`**，但在内核中根本不执行任何 VT 转换。
原 `01-Extended DLLs\KxBase\console.c` 假定“若 `SetConsoleMode` 原生返回 `TRUE`，则系统原生支持 VT”，导致 `Emulated = FALSE`，回写虚拟模式为 0，并触发 `BaseDisableConsoleAnsiSupport` 强行关闭了 ANSI 模拟器。所有 ANSI 字符直传 Win7 原生 `WriteConsoleA`，导致控制符全部乱码写屏。

### 根因二：跨缓冲区切分边界未决截断（CSI 粘包/断包缺陷）

Node.js / libuv 在流式写入时，缓冲区切分边界经常落在转义序列中间（例如块 1 末尾为 `\x1b[28;`，块 2 开头为 `1H`）。
原 `conansi.c` 遇到未完结序列时执行 `goto Exit` 并仅设置 `CchProcessed = 2`（只丢弃 `\x1b[`），剩下的 `28;` 在当前块被作为文本输出，下一块到达时的 `1H` 同样作为纯文本输出，导致屏幕上出现 `28;1H` 等漏码。

### 根因三：缺失 DEC Private Mode（`?` 前缀）与 `h` / `l` 命令（Mode Set/Reset）

现代终端 TUI 全面采用以下 DEC 私有模式：
1. **备用屏幕缓冲区（Alternate Screen Buffer: `\x1b[?1049h` / `\x1b[?1049l`）**：弹窗与全屏程序进入时必须切入备用屏幕缓冲区，退出时恢复主屏幕。原代码遇到 `?` 立即退出解析，且 `ExecuteCSI` 缺少 `case 'h'` 和 `case 'l'`，导致所有弹窗直接在主屏幕缓冲区上脏覆盖；
2. **光标显隐（DECTCEM: `\x1b[?25l` / `\x1b[?25h`）**：未实现；
3. **全屏与历史回滚清除（`\x1b[3J`）**：`ExecuteCSIErase` 缺少 `case 3`，被视为非法参数。

### 根因四：缺失 VT100 DEC 绘图字符集映射（`ESC ( 0` / `ESC ( B`）

TUI 边框与阴影通过 `ESC ( 0` 激活 DEC Line Drawing 字符集：
- `'a'` $\to$ `0x2592`（`▒` 阴影色块，用于 Logo 与立体边框）；
- `'q'` $\to$ `0x2500`（`─` 横线）；
- `'x'` $\to$ `0x2502`（`│` 竖线）；
- `'~'` $\to$ `0x00B7`（`·` 居中圆点）。
原代码未拦截 `ESC (`，控制台一直停在 US-ASCII 模式，导致阴影色块被渲染成大量 `'a'`。

## 3. 源码修复实施

### 3.1 `console.c` 修复模式捕获
确保 `ENABLE_VIRTUAL_TERMINAL_PROCESSING` (`0x0004` 等) 始终由 VxKex 内部仿真接管，剥离该位后传给 Win7 原生 conhost，并强制设置 `Emulated = TRUE`，激活 `BaseEnableConsoleAnsiSupport`。

### 3.2 `conansi.c` 增加未决流缓存（`g_PendingEscape`）
维护跨调用的 64 字符未决序列缓存：
- 当序列在当前缓冲区末尾未闭合时，暂存残片并消耗当次所有字节，阻止碎片漏到屏幕；
- 下次 `WriteConsole` / `WriteFile` 到达时，先与暂存碎片拼接合并解析，确保光标与模式命令无缝闭合执行。

### 3.3 `conansi.c` 实现 DEC 私有模式与备用屏幕缓冲区
- 支持解析 `?`、`>`、`!` 私有前缀；
- 实现 `case 'h'` 与 `case 'l'`：
  - **Mode 25**：调用 `SetConsoleCursorInfo` 控制光标显隐；
  - **Mode 1049 / 47 / 1047**：在内存中创建 `CHAR_INFO` 快照，使用 `ReadConsoleOutputW` 保存主屏幕视口文字与属性并清屏；退出时通过 `WriteConsoleOutputW` 100% 完美复原主屏幕与光标位置；
  - **Mode 1000/1002/1006/2004** 等：静默吸收，防止终端乱码。
- `ExecuteCSIErase` 扩展 `case 3:`，支持 `\x1b[3J` 擦除回滚行。

### 3.4 `conansi.c` 实现 DEC 绘图字符集映射
- 支持 `ESC ( 0` 开启与 `ESC ( B` 关闭 DEC Line Drawing 字符集；
- 在字符输出管道 `WriteConsoleTextAorW` 中将 `0x5F~0x7E` 即时映射为 Unicode 制表符与阴影色块，并通过 `WriteConsoleW` 绘制。
