# OpenCode 问答菜单上下键错乱、回车未提交与 VS Code 无反应排查解决

## 1. 现象与问题定义

用户在 Windows 7 SP1 x64 环境下运行 OpenCode（`opencode2-node`）触发多选问答交互（`Questions` / `ask_question` 组件）时，分别在独立 `pwsh` 控制台与 VS Code 集成终端中观察到以下现象：

1. **现象一（独立 `pwsh`）**：在选项列表中按上下方向键切换选中项时，界面文本发生错位与重复覆盖（例如 `| 1. [ ] 写代码 / 改文件 位 bug、给出修复方案`，标题文字覆盖在上一帧的描述文字上且右侧残留碎片），底部的快捷键提示重复出现并随着按键不断向下漂移；
2. **现象二（独立 `pwsh`）**：在选项上按下回车键（`Enter`），界面虽然将当前项打上了勾选标记（`[✓]`），但并未进入下一步，依然停留在问答界面；
3. **现象三（VS Code 集成终端）**：在打开的问答界面中，按下方向键（`↑` / `↓`）没有任何反应，选项列表中没有焦点光标 `|`。

---

## 2. 根本原因与机制剖析

通过对 `@opencode/cli-node`（`opencode2-node.exe`）内置的 Solid/opentui 前端表单引擎源码逆向提取，以及通过 Node.js + `node-pty`（`winpty-agent`）进行按键输入流链路实测，查明三项现象的底层机制如下：

### 2.1 现象二根因：多选问答（Multi-Select）的按键契约逻辑

查看 `opencode2-node.exe` 中 `Question` 组件的键盘事件处理逻辑（`useKeyboard`）：

```javascript
return useKeyboard(An => {
    if (cn().submitting) { An.preventDefault(); return; }
    if (An.name === "escape") { jn(), An.preventDefault(); return; }
    if (An.name === "tab" || An.name === "left" || An.name === "right" || An.name === "h" || An.name === "l") {
        const Jn = An.shift || An.name === "left" || An.name === "h" ? -1 : 1;
        Un(Jn), An.preventDefault();
        return;
    }
    if (yn() && An.name === "return") {
        Nn(), An.preventDefault();  // 仅在 yn() 为真（焦点在 Submit 状态）时回车提交
        return;
    }
    const Mn = wn().length + (vn() ? 1 : 0), Vn = Number(An.name);
    if (!Number.isNaN(Vn) && Vn >= 1 && Vn <= Math.min(Mn, 9)) {
        Hn(Vn - 1), An.preventDefault();  // 支持直接按数字键 1~9 选择
        return;
    }
    if (An.name === "up" || An.name === "k") {
        pn(Jn => formMove(Jn, ct.request, -1)), An.preventDefault();
        return;
    }
    if (An.name === "down" || An.name === "j") {
        pn(Jn => formMove(Jn, ct.request, 1)), An.preventDefault();
        return;
    }
    An.name === "return" && (Hn(), An.preventDefault()); // 选项上按回车执行 Hn() 切换勾选
});
```

- **`Enter` 键的语义是 `toggle`（切换勾选）**：
  在多选问答模式（`(可多选)` / `multiselect`）下，按 `Enter`（或 `Space`）执行的是 `Hn()`，即切换当前选项的复选框状态（`[ ]` ↔ `[✓]`）。组件底部的操作提示明确标明了 `enter toggle`；
- **提交需按 `Tab` 键切换至 `Submit`**：
  底栏提示中的 `* tab` 标明了 `Tab` 键的作用。用户勾选完毕后，必须按 **`Tab`** 键将焦点移至右上角的 **`Submit`** 按钮（此时 `yn()` 变为 `true`，底栏变为 `enter submit`），此时再按 **`Enter`** 才会调用 `Nn()` 提交表单进入下一步。
- **结论**：按回车未进入下一步**不是故障，而是多选题的交互操作设计**（单选回车立即提交，多选回车仅切换选中状态）。

### 2.2 现象一根因：普通屏幕缓冲区视口触底滚动破坏了光标回退锚点

在独立 `pwsh` 控制台中，用户未配置环境变量 `$env:OTUI_USE_ALTERNATE_SCREEN = "true"`，程序运行在**主屏幕缓冲区（Inline / Split-footer 模式）**：

1. **聊天历史与高组件引发视口触底**：
   - 终端上方保留了之前的聊天流历史文本（约 15 行）；
   - 当前多选问答共有 7 个选项，前 6 项均由“标题行 + 描述行”组成（每项 2 行），加上标题、提示、底栏等，组件总高超过 18 行；
   - 总高度（15 + 18 = 33 行）超过了 Windows 7 conhost 控制台视口高度（通常为 25~30 行）；
   - 在首次输出时，光标触及控制台窗口底部，conhost **被迫发生了整屏物理上卷（Scroll Up）**。
2. **物理上卷导致 ANSI 光标回退失真**：
   - OpenCode 在每次按键触发组件重新渲染时，按照组件的逻辑高度（$H$ 行）发送 `\x1b[<H>A`（Cursor Up）试图回退到组件起始行；
   - 但因为部分行已被卷出视口，Win7 conhost 在 `conansi.c` 中的 `VTClampCursorPosition` 将光标 Y 限制在 `[srWindow.Top, srWindow.Bottom]`，回退行数被硬性截断在视口顶部；
3. **2 行选项与 1 行步长交错覆盖**：
   - 向上回退不足导致起始重绘点向下偏离了 1 行；
   - 当打印选项 1 的标题（`| 1. [ ] 写代码 / 改文件`）时，恰好打印在了上一帧选项 2 的描述行（`       定位 bug、给出修复方案`）；
   - 由于输出短字符串时未发清行指令，原有描述行的后半截（`位 bug、给出修复方案`）残留在右侧，呈现为极度混乱的交错拼合（`| 1. [ ] 写代码 / 改文件 位 bug、给出修复方案`）；
   - 每次按键，由于高度漂移累加，底栏提示也随之向下多印了一次。

### 2.3 现象三根因：VS Code 驱动链路正常，组件处于 Submit 确认态或窗口失焦

针对 VS Code 集成终端中上下键无反应的现象，进行了输入链路探测：

1. **底层按键传输链路实测通过**：
   编写探测脚本 `test_winpty_keys.js`，通过 VS Code 自带的 `node-pty`（`winpty-agent.exe`，`useConpty: false`）向 Node.js 进程注入键盘序列：
   - 注入 `\x1b[A`（Up） -> Node.js 完整收到 `[0x1b, 0x5b, 0x41]`；
   - 注入 `\x1b[B`（Down） -> Node.js 完整收到 `[0x1b, 0x5b, 0x42]`；
   - 注入 `\r`（Enter） -> Node.js 完整收到 `[0x0d]`；
   - 注入 `\t`（Tab） -> Node.js 完整收到 `[0x09]`；
   实测证明：Win7 下 VS Code 的 `winpty` 代理能够 100% 准确、无损地将方向键转译为 Win32 `KEY_EVENT` 并交付给应用程序，**不存在底层驱动拦截或丢失按键的缺陷**。
2. **表单状态处于 `Submit` 聚焦态**：
   观察图 2 现场界面：
   - 标题行为 `下一步 Submit`，下方 5 个选项前**均无聚焦指示符 `|`**（纯数字 `1. [ ]`, `2. [ ]`）；
   - 查看表单移动逻辑 `formMove`：
     ```javascript
     function formMove(ct, $t, en) {
         const tn = formCurrent($t, ct),
             nn = formRows(tn).length + (formCustom(tn) ? 1 : 0);
         return nn === 0 ? ct : { ...ct, selected: (ct.selected + en + nn) % nn, error: "" };
     }
     ```
   - 当焦点移至 `Submit` 按钮时，`field >= fields.length`，`formCurrent` 返回 `undefined`，`formRows` 长度为 0（`nn === 0`）；
   - 此时 `formMove` 直接返回原状态 `ct`，**上下方向键在此状态下设计即为无操作（No-op），因此没有任何视觉变化**；
   - 此时若按 **`Enter`** 键，会直接提交表单；若想切回选项列表，按 **`Tab`** 或 **`Left Arrow (←)`** 即可恢复选项列表的聚焦光标 `|`。
3. **窗口失焦排查**：
   若鼠标点击过 VS Code 编辑器区，集成终端面板可能处于失焦状态，按键被外层捕获。点击终端面板内任意位置即可恢复终端焦点。

## 3. 解决措施与操作指引

### 3.1 渲染错乱根治方案（消除 pwsh 界面重叠与漂移）

强烈推荐在运行 OpenCode 前启用**备用屏幕缓冲区（Alternate Screen Buffer）**：

#### 方案 1：在当前会话或 Profile 中配置（强烈推荐）
在 `pwsh` 终端中执行或写入 `$PROFILE`：
```powershell
$env:OTUI_USE_ALTERNATE_SCREEN = "true"
```
- **作用效果**：
  OpenCode 将自动发送 `\x1b[?1049h` 切换至独立备用屏幕。在备用屏幕下，整个 TUI 界面固定在 `[0, Rows-1]` 视口内，不产生任何历史推挤和视口滚动截断，所有问答菜单和底栏绝对稳定，彻底杜绝交错重叠与残影。

#### 方案 2：扩大控制台窗口高度
若需要在主屏幕缓冲区下保留历史流，请将独立控制台窗口最大化，或将控制台视口高度调整为 **45 行以上**，避免由于 15 行历史 + 18 行菜单触碰窗口底边而触发滚动截断。

---

### 3.2 交互操作操作指引（多选表单）

针对 OpenCode 的交互式问答（`Questions`）组件，标准操作流程如下：

| 操作目标 | 推荐按键 | 详细说明 |
| :--- | :--- | :--- |
| **切换选项** | `↑` / `↓`（或 `k` / `j`） | 在选项之间移动高亮光标 `\|` |
| **快速勾选** | 数字键 `1` ~ `9` | 直接按对应数字键切换该项的选中状态 |
| **切换选中状态** | `Enter`（或 `Space`） | 仅在选项有焦点时生效，切换 `[ ]` ↔ `[✓]`，不提交 |
| **切换至提交按钮** | `Tab`（或 `→`） | 将焦点移至右上角的 `Submit` 按钮 |
| **返回选项列表** | `Shift+Tab`（或 `←`） | 从 `Submit` 按钮切回选项列表，恢复方向键导航 |
| **正式提交** | 焦点在 `Submit` 时按 `Enter` | 提交当前已勾选的选项并进入下一步 |
| **退出问答** | `Esc` | 取消问答组件 |

---

## 4. 验证结论

1. **回车未提交**：属 OpenCode 多选表单正常行为，按 `Tab` 移至 `Submit` 后回车即可提交；
2. **VS Code 上下键无反应**：焦点已在 `Submit` 上（或终端失焦），按 `Tab` 或 `←` 可切回列表；
3. **pwsh 上下键错乱**：由普通屏幕缓冲区触底滚动截断光标回退导致，通过 `$env:OTUI_USE_ALTERNATE_SCREEN = "true"` 启用备用屏幕缓冲区即可 100% 根除。
