## 官方接口契约

2026-10-13 查阅 Microsoft Learn 的 CreatePseudoConsole、ResizePseudoConsole、ClosePseudoConsole 页面。来源地址记录如下（仅为资料，不是执行命令）：

```text
https://learn.microsoft.com/en-us/windows/console/createpseudoconsole
https://learn.microsoft.com/en-us/windows/console/resizepseudoconsole
https://learn.microsoft.com/en-us/windows/console/closepseudoconsole
```

- CreatePseudoConsole：HRESULT WINAPI，参数依次为 COORD、HANDLE、HANDLE、DWORD、HPCON*。
- ResizePseudoConsole：HRESULT WINAPI，参数依次为 HPCON、COORD。
- ClosePseudoConsole：void WINAPI，参数为 HPCON；没有返回值。
- 创建和调整尺寸成功返回 S_OK，失败返回 HRESULT 错误码。文档未规定“Win7 无后端”必须返回哪一个失败码。
- 创建输出为伪控制台句柄；不能凭空返回有效句柄。关闭接口的输入应是创建所得的活动伪控制台，不可当作普通内核句柄随意 CloseHandle。
- 官方最低客户端为 Windows 10 1809。以上契约不代表 Win7 原生具备后端。

## 建议补丁（仍需调用方核验）

1. 优先在已有 `D:\project\VxKex-NEXT\01-Extended DLLs\KxBase\console.c` 添加实现，在 `D:\project\VxKex-NEXT\00-Common Headers\KxBase.h` 添加旧 SDK 所需类型和原型，在 `D:\project\VxKex-NEXT\01-Extended DLLs\KxBase\kxbase.def` 添加三个不带修饰的导出。复用已有编译项，不增加源码文件。
2. 使用现有 KXBASEAPI、WINAPI、IN/OUT、制表符及声明风格；HPCON 类型需核对 SDK 定义和保护条件，不能在现代 SDK 下重复声明冲突。Win32 必须检查 stdcall 栈平衡和导出名称，不能仅凭 x64 检查推定通过。
3. 创建无后端时，建议对空输出指针返回 E_INVALIDARG，对可写输出位置清零后返回 HRESULT_FROM_WIN32(ERROR_NOT_SUPPORTED)。这是本项目拟定的失败策略，不是官方指定的失败码。尺寸、flags 等参数检查优先级待最终确定，不猜测原生实现的所有错误细节。
4. Resize 无后端时明确失败，不返回 S_OK；空/无效句柄的具体错误策略待调用方核验后固定。
5. Close 没有 HRESULT 返回通道。由于创建接口不会生成句柄，NULL 清理可设计为无操作；非空句柄应记录不支持警告且不能调用 CloseHandle 或解引用陌生指针。不得把这个导出称为实现了真正的关闭语义，也不应凭空承诺 GetLastError 契约。
6. 不实现伪控制台进程属性、不伪造句柄、不把普通匿名管道当成 ConPTY。即使解除加载阻断，交互和子进程功能仍需单独评估。
