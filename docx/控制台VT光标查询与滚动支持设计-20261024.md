# 控制台 VT 光标位置查询（CPR）与视口滚动支持设计

## 1. 背景与问题定义

在 Windows 7 SP1 x64 环境下运行 `opencode2-node` 等现代化交互式 TUI 应用程序时，在进入聊天会话（Continuation / Session）后，输入框未在固定底栏呈现，且光标随着标准输出流向下方离散漂移（例如第 25 行、第 34 行），导致用户输入位置无法固定。

### 1.1 缺陷根因
1. OpenCode/opentui 默认采用 `split-footer` 混合分屏模式：
   - 顶部区域输出流式对话文本（stdout / scrollback）；
   - 底部保留固定行高（`FOOTER_HEIGHT`）的常驻底栏（输入框与状态行）。
2. 为了在滚动的聊天历史下方锚定底栏，TUI 强依赖现代终端的以下转义控制：
   - **`CSI 6n`（DSR / CPR 光标位置查询）**：TUI 写入历史后发送 `\x1b[6n` 询问终端当前物理光标所在行列，终端应回写 `\x1b[<row>;<col>R` 到标准输入（STDIN）；
   - **`CSI S`（Scroll Up，内容上卷）/ `CSI T`（Scroll Down，内容下卷）**：为固定底栏腾出空间；
   - **`CSI r`（DECSTBM 设置/重置滚动区域）**：重置滚动区域，并将光标复位到 Home `(1, 1)`。
3. **VxKex 当前仿真层盲区**：
   - 在 `01-Extended DLLs/KxBase/conansi.c` 的 `ExecuteCSI` 中，缺少 `case 'n':`、`case 'S':`、`case 'T':` 与 `case 'r':` 处理；
   - 当 OpenCode 发出 `\x1b[6n` 查询光标行号时，`KxBase` 直接丢弃该指令，从未向输入队列回送响应；
   - OpenCode 等待 120ms 超时后，只能假定光标行号为 0 或未初始化，导致底栏被错误绘制在中间第 9~12 行，而真正的物理光标遗留在终端最底部，用户按键输入直接落在裸控制台的游离行上。

## 2. 补丁架构设计

### 2.1 增加 `VTScrollDisplay` 视口滚动支持（`consup.c` / `kxbasep.h`）
利用 Win32 Console 原生 API `ScrollConsoleScreenBufferW` 实现视口滚动：
- **函数签名**：
  ```c
  BOOLEAN VTScrollDisplay(
      IN  HANDLE  ConsoleHandle,
      IN  SHORT   Lines);
  ```
- **参数语义**：
  - `Lines > 0`（Scroll Up，对应 `CSI S`）：可视区内容向上卷动 `Lines` 行，底部出现新的空白行；目标坐标 `DestCoord.Y = srWindow.Top - Lines`；
  - `Lines < 0`（Scroll Down，对应 `CSI T`）：可视区内容向下卷动 `|Lines|` 行，顶部出现新的空白行；目标坐标 `DestCoord.Y = srWindow.Top - Lines`；
  - `Lines == 0`：空操作，直接返回 `TRUE`；
- **填充属性**：统一使用空白字符 `L' '`，属性使用当前窗口默认文本属性 `Sbi.wAttributes`，裁剪区域严格限定在视口矩形 `Sbi.srWindow` 内。

### 2.2 在 `ExecuteCSI` 中支持 `case 'n':`（Device Status Report / CPR）
- **`CSI 6n`（Cursor Position Report）**：
  - 调用 `VTGetCursorPosition(ConsoleHandle, &CursorPosition)` 获取相对于视口的 1-based 光标坐标 `(CursorPosition.Y, CursorPosition.X)`；
  - 格式化标准响应字符串：
    - 常规模式：`\x1b[%hd;%hdR`；
    - DEC 专用模式（`IsPrivateMode == TRUE`，即 `CSI ? 6 n`）：`\x1b[?%hd;%hd;1R`；
  - 调用 `InjectStringToConsoleInput(GetStdHandle(STD_INPUT_HANDLE), Response)` 将响应模拟为键盘输入注入控制台输入队列；
- **`CSI 5n`（Device Status Report）**：
  - 返回状态正常指示 `\x1b[0n`（Ready, no malfunction detected）。

### 2.3 在 `ExecuteCSI` 中支持 `case 'S':` 与 `case 'T':`
- **`case 'S'`（Scroll Up / Pan Down）**：
  - 滚动行数 `Lines = max(1, CsiParameters[0])`；
  - 调用 `VTScrollDisplay(ConsoleHandle, Lines)`；
- **`case 'T'`（Scroll Down / Pan Up）**：
  - 滚动行数 `Lines = max(1, CsiParameters[0])`；
  - 调用 `VTScrollDisplay(ConsoleHandle, -Lines)`。

### 2.4 在 `ExecuteCSI` 中支持 `case 'r':`（DECSTBM / 边距重置）
- 按照 ANSI/VT100 规范，执行 `DECSTBM`（设置/复位滚动区）时必须将光标复位到第一行第一列：
  ```c
  case 'r': {
      COORD Home = {1, 1};
      return VTSetCursorPosition(ConsoleHandle, Home);
  }
  ```

## 3. 影响范围与回归安全性
- **模块独立性**：修改严格局限在 `01-Extended DLLs/KxBase/consup.c` 与 `01-Extended DLLs/KxBase/conansi.c`；
- **ABI 与导出**：不改变任何公有导出函数与签名，不改动数据结构大小；
- **向后兼容性**：原有 ANSI 序列解析不受任何负面影响，所有新增分支仅在遇到此前报错未识别的 `'n'`、`'S'`、`'T'`、`'r'` 时触发；
- **回归测试覆盖**：原有 `test/x64/Release/ansi-features-test.exe` 与 `terminal-redraw-test.exe` 继续保证无断言失败。
