# OpenCode 斜杠菜单显示偏离正中与界面重绘漂移排查解决

## 1. 问题背景与现象描述

在 Windows 7 专业版 SP1 x64（Build 7601）环境下运行 `opencode2-node.exe` 时，用户反馈在主界面键入斜杠命令（`/`）唤出模型选择或命令菜单、以及按 `Esc` 退出斜杠菜单时，界面显示出现严重的**偏离正中心**与**横向右移漂移**现象。

## 2. 根本原因深度分析

通过反编译解析 `opencode2-node.exe` 的内嵌单文件打包结构（Single Executable Application），发现其架构由 Solid.js 前端 + opentui + Facebook Yoga Flexbox 布局引擎 + 原生动态库（`PE at offset 168333143`）构成。造成偏离居中与右移漂移的核心机制如下：

### 2.1 Yoga 布局居中计算与控制台物理光标脱节
OpenCode 的对话框与主输入卡片通过 Yoga 的 Flexbox 居中规则对齐：
$$\text{PaddingLeft} = \left\lfloor \frac{\text{TerminalColumns} - \text{BoxWidth}}{2} \right\rfloor$$
- 在旧会话启用了 `chcp 65001 (UTF-8)` 的状态下，Windows 7 原生 `conhost.exe` 存在宽字符（CJK 汉字、点阵框线符）处理缺陷：写入汉字时光标仅推进 1 列而非 2 列，导致实际光标物理坐标与 TUI 逻辑计算的坐标出现持续累积偏差。
- 此外，旧版 `KxBase.dll` 中 `WriteConsoleUnicodeText` 人工添加了盲目的双格递增代码，导致在某些控制台调用路径下光标反而跳格推进。
- 这种虚拟坐标与物理坐标的偏差使得 TUI 在进行相对光标重绘（Relative Cursor Movement）时，从已经偏移的基准点开始输出，直接将居中框体推向了屏幕右半区。

### 2.2 PowerShell `PSReadLine` 的中间层拦截与脏状态残留
PowerShell 7 默认加载的 `PSReadLine` 模块会在控制台标准输入输出之间插入一层虚拟行编辑器（Line Editor）。
- 在运行交互式 TUI 应用前，`PSReadLine` 会拦截控制台的 VT 序列与按键事件，并在缓冲区中保存当前行的渲染状态。
- 当在 `pwsh` 中启动 `opencode2-node` 时，若 `PSReadLine` 模块未被卸载，其遗留的行编辑上下文会导致应用初次获取控制台几何信息与初始光标锚点时带入非零偏移量；
- 当按下 `/` 键触发搜索弹窗时，TUI 发送清行和重绘指令，而 conhost 在 `PSReadLine` 污染的行状态下未能将光标归零，导致重绘从上一级遗留的横向位置开始拼接。

### 2.3 旧进程未载入修复版 DLL
- 之前编译好的新版 `KxBase.dll`（移除了人工双格 Bug，支持 DECAWM 换行模式）已由安装包更新至 `C:\Program Files\VxKex\Kex64\KxBase.dll`；
- 但在用户最初复现该现象时，终端窗口可能仍运行在尚未退出的旧 `pwsh.exe` 进程中，依然加载着旧版 DLL。

## 3. 解决措施与生效机制

该问题通过以下三项系统性的环境净化与底层修复实现彻底解决：

### 3.1 彻底移除 Profile 中的 `chcp 65001`，恢复原生代码页 CP936
将用户目录下所有 4 个 PowerShell Profile（`PowerShell` 与 `WindowsPowerShell` 下的 `profile.ps1` 及 `Microsoft.PowerShell_profile.ps1`）中的 UTF-8 强制切换移除，保持系统原生 **CP936（GBK）**：
- Windows 7 conhost 在 CP936 下对 CJK 双列宽具有原生硬件级支持，每个中文字符与双宽符号严格占据 2 列；
- 避免了 UTF-8 模式下宽字符列宽在 1 列与 3 列之间抖动的问题，彻底消除了导致光标与布局脱节的累积位移源头。

### 3.2 在 Profile 中全局禁用 `PSReadLine` 模块
在 PowerShell 配置文件中注入自动卸载逻辑，杜绝任何中间层行缓冲干扰：
```powershell
# Disable PSReadLine to avoid VT rendering artifacts on Windows 7 / winpty
if (Get-Module -Name PSReadLine) {
    Remove-Module PSReadLine -ErrorAction SilentlyContinue
}
```
**生效机制**：
- 确保 `opencode2-node` 能够独占控制台输入输出流，直接与 Windows 控制台子系统交互；
- 不再受 `PSReadLine` 内部光标状态同步错误的干扰，弹窗与子组件重绘时基准锚点始终与真实屏幕原点严格重合。

### 3.3 部署新版 `KxBase.dll`（统一由系统底层 WriteConsole 处理宽字符）
用户通过运行最新发布的安装包 `KexSetup_Release.exe`，成功将新编译的 `KxBase.dll` 部署到目标系统：
- **目标路径**：`C:\Program Files\VxKex\Kex64\KxBase.dll`（160,768 字节，SHA256: `fb5ede21...`）；
- **核心修复**：[conansi.c](file:///D:/project/VxKex-NEXT/01-Extended%20DLLs/KxBase/conansi.c#L1064-L1071) 中彻底移除了导致字符双写和跳格的人工推进代码，直接透传系统 `WriteConsoleW`；
- **换行支持**：支持了 `\x1b[?7h` 与 `\x1b[?7l`（DECAWM 自动换行控制），确保屏幕到达右边界时不会意外折行或溢出。

### 3.4 开启新会话重置控制台几何上下文
在新打开的控制台窗口中，上述改动同时生效：
- 代码页为纯净的 CP936；
- 无 `PSReadLine` 干扰；
- 进程已加载新版 `KxBase.dll`；
- 控制台缓冲区从 `(0, 0)` 初始对齐，Yoga 居中计算精确落入屏幕中线。

## 4. 验证与验收结论

### 4.1 验收结果
用户在更新配置并打开新终端后实测确认：
1. **居中稳定**：进入斜杠命令（`/`）时，弹出的模型列表与命令面板稳定显示在控制台正中央；
2. **退出无漂移**：按 `Esc` 退出斜杠菜单后，主界面的 Logo、输入框和底部快捷键提示全部平滑恢复到原始居中位置，**不再向右跳动漂移**，两边留白完全对称；
3. **残留擦除干净**：之前残留在弹窗左侧的 `Ask`、`Buil`、`~` 字符及右侧虚线彻底消失；
4. **中文输入对齐**：输入“继续”等中文词汇正常双列宽显示，占位提示词被完整覆盖，无多余英文字母夹杂。
