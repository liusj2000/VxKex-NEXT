## 一、测试对象与目标

- 对象：`01-Extended DLLs\KxBase` 的伪控制台补丁（`CreatePseudoConsole` / `ResizePseudoConsole` / `ClosePseudoConsole` + `Ext_CreateProcessA/W` 桥接）。
- 待测产物：`D:\project\VxKex-NEXT\x64\Release\KxBase.dll`（2026-10-13 用 Windows7.1SDK 工具链编译，154,112 字节，142 个导出，含 `ClosePseudoConsole` 序号 190）。
- 目标：证明它在 Win7 SP1 x64 上**行为正确**，而不只是"能加载"；并明确记录它与 Windows 10 原生 ConPTY 的语义差异。
- 重要前提：当前实现是**管道式后端**（把调用方的输入/输出句柄复制为可继承句柄，子进程改用 `STARTF_USESTDHANDLES`），不是控制台缓冲区/逐像素等价实现。测试期望按管道语义设定，差异必须记录，不能当作原生 ConPTY 通过。

### A. 加载与导出层（不需要改代码）

| 编号 | 用例 | 期望 | 判据 |
| --- | --- | --- | --- |

### B. API 契约层（自写最小 C 测试程序，用同一工具链编译）

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| B1 | `CreatePseudoConsole` 参数校验：`Size` 为 0/负、`InputHandle`/`OutputHandle` 为 NULL 或无效句柄、`PseudoConsoleHandle` 为 NULL | 返回失败（`E_INVALIDARG`/`E_HANDLE` 类），**不产生假句柄、不返回 S_OK** |
| B2 | 合法管道句柄 → 成功路径 | 返回 `S_OK` 且 `*PseudoConsoleHandle` 非空；可同时创建多个实例且互不干扰 |
| B3 | `ResizePseudoConsole`：合法句柄、非法句柄、`Close` 之后的句柄 | 合法更新尺寸；非法/已关闭返回失败，不崩溃 |
| B4 | `ClosePseudoConsole` 生命周期 | 释放内部对象；**不关闭调用方原始句柄**（调用方仍能对自己那端 `ReadFile`/`WriteFile`）；重复调用不崩溃或有明确失败返回 |
| B5 | 句柄继承 | 内部复制句柄可继承；调用方句柄即使非继承，子进程仍能正常读写 |

### C. `CreateProcess` 集成层

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| C1 | `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE` + `UpdateProcThreadAttribute` 启动 `cmd.exe` | 管道中读到命令提示符/命令回显；能取得子进程退出码 |
| C2 | stdin 注入 `echo hello` + 换行 | 输出包含 `hello` |
| C3 | 与 `EXTENDED_STARTUPINFO_PRESENT` 组合；与 `CREATE_NEW_CONSOLE` 冲突时 | 组合可用；冲突时行为明确（失败或按文档降级），不能静默产生无控制台子进程 |
| C4 | `ClosePseudoConsole` 之后 | 读端收到 EOF（`ReadFile` 返回 0 / `ERROR_BROKEN_PIPE`），子进程被正确终止，不残留进程 |
| C5 | 伪造/已关闭的 `HPCON` 传给 `CreateProcess` | 必须失败，**不能**启动一个没有正确控制台的子进程 |
| C6 | 句柄与资源泄漏 | 创建/销毁 N（建议 ≥200）轮后，进程句柄数不持续增长；`cmd.exe` 进程不残留 |
| C7 | 高负载 | 大量输出/大缓冲不死锁；并发多实例不互相串流 |

## 六、已知风险与边界

- 管道式后端与原生 ConPTY 存在语义差异（无控制台缓冲区、无 VT 逐像素/属性语义、无真正的 resize 效果），必须显式记录差异清单。
- 新 DLL 未做任何运行验证；替换后故障会波及所有被注入进程，需先写好回滚步骤并确认用户可即时操作。
- 本机 VxKex 导入重写崩溃缺陷未修，测试期间可能偶发干扰编译器/工具进程，遇到时先排除该因素再判定被测实现。
- 未获用户明确安排前：不替换系统或安装目录 DLL、不改 IFEO/版本伪装/传播设置、不运行安装器。
