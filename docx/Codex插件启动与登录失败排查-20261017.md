# Codex 插件无法显示登录界面排查与根因分析（2026-10-17）

## 一、现象与用户问题

用户在 Windows 7 SP1 x64 环境下使用 VS Code（`D:\VSCode-win32-x64-1.107.1` 便携版）启动后，Codex 插件（`openai.chatgpt-26.1007.21434-win32-x64`）无法显示登录界面。

**诊断结论**：
- 错误码 `3221225785` 即十六进制 **`0xc0000139` (`STATUS_ENTRYPOINT_NOT_FOUND`)**。
- `codex.exe`（后台 `app-server`）因缺少静态导入符号，在进程启动阶段被 Windows NT 加载器直接终止。
- 由于后台服务崩溃，前端 Webview 向其发送 `account/read`、`getAuthStatus` 均返回 `write EPIPE`，因此 Webview 无法获取认证状态，无法呈现登录界面。

### 2. 二进制导入表全面扫描结果
通过编写自动化扫描脚本 `test\check_all_codex_binaries.ps1`，对插件目录（`D:\VSCode-win32-x64-1.107.1\data\extensions\openai.chatgpt-26.1007.21434-win32-x64\bin\windows-x86_64\`）下全部 5 个可执行程序进行重定向导入对照：

1. **`codex.exe`**：
   - 缺失 `IsApiSetImplemented`：
     - 导入模块：`api-ms-win-core-apiquery-l2-1-0.dll`
     - VxKex 重定向目标：`kxnt.dll`（`C:\Program Files\VxKex\Kex64\kxnt.dll`）
     - 现状：`kxnt.dll` 仅导出了 `ApiSetQueryApiSetPresence`（来自 `KexDll`），**未导出 `IsApiSetImplemented`**。
   - 缺失 `DeriveCapabilitySidsFromName`：
     - 导入模块：`api-ms-win-security-base-l1-2-2.dll`
     - VxKex 重定向目标：`kxbase.dll`（`C:\Program Files\VxKex\Kex64\kxbase.dll`）
     - 现状：`kxbase.dll` **未实现也未导出 `DeriveCapabilitySidsFromName`**。
2. **`codex-code-mode-host.exe`**：
   - 静态导入 `dbghelp.dll!malloc_h`（符号解析相关，可通过延迟加载或补充 forward 处理）。
3. **`codex-command-runner.exe`**：全部符号满足（0 缺失）。
4. **`codex-windows-sandbox-setup.exe`**：全部符号满足（0 缺失）。
5. **`rg.exe`**：全部符号满足（0 缺失）。

### 3. 关于 ConPTY 导出的核实
经实测验证，已部署的 `C:\Program Files\VxKex\Kex64\kxbase.dll` 已具备以下导出：
- `ClosePseudoConsole`（序数 401，RVA 0x0000270C）
- `CreatePseudoConsole`（序数 495，RVA 0x00002464）
- `ResizePseudoConsole`（序数 1548，RVA 0x00002688）

因此 ConPTY 核心三函数已存在，真正的 `0xc0000139` 阻断点是上述 **`IsApiSetImplemented`** 与 **`DeriveCapabilitySidsFromName`**。

## 三、修复方案与技术设计

### 1. 补齐 `IsApiSetImplemented`
- **函数契约**：
  ```c
  BOOL WINAPI IsApiSetImplemented(
      IN PCSTR Contract);
  ```
- **模块位置**：`01-Extended DLLs\KxNt`（并导出在 `kxnt.def`），或由 `KexDll` 实现后在 `kxnt` 导出。
- **实现逻辑**：
  调用现有的 `ApiSetQueryApiSetPresence` / `KexLdrGetDllFullName`，或者由于 Win7 兼容层已经内置了所有重定向映射，对于已知重定向表中的 API Set 直接返回 `TRUE`；通用兜底返回 `TRUE`。

### 2. 补齐 `DeriveCapabilitySidsFromName`
- **函数契约**：
  ```c
  BOOL WINAPI DeriveCapabilitySidsFromName(
      IN  PCWSTR CapName,
      OUT PSID   CapabilityGroupSid,
      OUT PSID   CapabilitySid);
  ```
- **模块位置**：`01-Extended DLLs\KxBase`（`security.c`）并导出在 `kxbase.def`。
- **实现逻辑**：
  AppContainer 功能在 Win7 上原生不存在。参照 Wine `dlls/advapi32/security.c` 规范：
  若是查询已知标准 capability，可分配构造适当的 SID；若不支持则调用 `SetLastError(ERROR_CALL_NOT_IMPLEMENTED)` 并返回 `FALSE`。此举可确保 PE 导入表加载成功，使 `codex.exe` 正常进入运行时，内部根据返回值退回普通模式。

## 四、验证步骤

1. 在 `KxNt` 与 `KxBase` 中添加上述两函数的声明、实现与 def 导出。
2. 运行 `build-installer.cmd` 全量构建 x64 与 Win32 DLL，并生成更新安装包 `KexSetup_Release.exe`。
3. 重新运行 `test\check_all_codex_binaries.ps1`，确认 `codex.exe` 缺失符号数归 0。

5. 在 VS Code 中打开 Codex 插件，确认后台 `codex app-server` 正常运行，登录界面成功渲染。
